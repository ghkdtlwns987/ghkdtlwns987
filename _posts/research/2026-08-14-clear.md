## Summary
기존 LLM 기반 소프트웨어 취약점 탐지 기법은 코드의 의미적 유사성이나 LLM의 내부 지식에 크게 의존하기 때문에, 취약 코드와 패치 코드가 구조적으로 매우 유사한 경우 정확하게 구분하지 못하는 한계가 있다. 본 연구는 이러한 문제를 해결하기 위해 취약점을 단순한 코드 패턴이 아닌 **인과적 과정(Causal Process)**으로 표현하고 이를 Multi-Agent의 추론 근거로 활용하는 **CLEAR(Causal Context-Based Agentic Reasoning)**를 제안했다.

CLEAR의 핵심은 **Vulnerability Causal Knowledge Graph(VCKG)**이다. VCKG는 하나의 취약점을 **Entrypoint, Precondition, Root Cause, Fix Intent, CWE**로 구조화하고, 이를 인과 관계로 연결한다. 특히 Fix Intent를 명시적으로 표현하여 코드 자체가 유사하더라도 취약점의 원인이 실제로 제거되었는지를 판단할 수 있도록 설계하였다. VCKG는 Local VCKG Construction, Neighbor Edge Integration, Global Edge Integration의 세 단계를 통해 구축된다.

구축된 VCKG는 네 개의 에이전트가 활용한다.

- **Collector Agent**: 대상 코드와 관련된 Causal Context 검색

- **Claim Agent**: 검색된 근거를 기반으로 취약점 Hypothesis 생성

- **Critic Agent**: Precondition과 Fix Intent 등을 이용해 Claim을 반박·검증

- **Judge Agent**: 양측의 주장과 근거를 종합하여 최종 취약 여부와 CWE 결정

즉, CLEAR는 단순히 여러 LLM이 토론하도록 하는 것이 아니라, **검색된 Causal Evidence를 중심으로 Multi-Agent Reasoning을 수행한다는 점**이 특징이다. Claim Agent는 검색된 Causal Path를 기반으로 가설을 생성하고, Critic Agent는 해당 가설이 실제 코드 상태에서 성립하는지를 반대로 검증한다. CLEAR.pdf

실험은 C/C++ 기반 **PrimeVul**과 CVEFixes, MegaVul, CleanVul을 이용해 구성한 Java 기반 **Java-Pair** 데이터셋에서 수행되었다. CLEAR는 PrimeVul과 Java-Pair에서 기존 Multi-Agent SOTA 대비 P-C를 각각 **130.7%, 71.56% 향상**시켰으며, CWE Classification에서도 기존 Multi-Agent 방법보다 높은 성능을 기록하였다. CLEAR.pdf

Ablation Study에서도 VCKG를 제거하고 Agent만 사용했을 경우 PrimeVul의 P-C가 **19.17에서 8.08**로 크게 감소하였다. 특히 Precondition, Root Cause, Fix Intent를 제거했을 때 성능 저하가 크게 나타나, 단순한 코드 유사성보다 **취약점의 발생 조건, 근본 원인, 패치 의도와 같은 Causal Evidence가 중요함**을 확인하였다. CLEAR.pdf

또한 30개의 VCKG를 대상으로 전문가 평가를 수행한 결과 Local VCKG 4.83/5.0, Neighbor Edge 3.58/5.0, Global Edge 4.14/5.0을 기록하여 생성된 Causal Knowledge의 품질도 함께 검증하였다.

## Paper Review

기존 LLM 기반 소프트웨어 취약점 탐지 연구는 크게 Prompting, RAG, Multi-Agent 방식으로 발전해 왔다. 특히 최근에는 Vul-RAG와 같이 과거 취약점으로부터 일반화된 지식을 추출하여 LLM의 판단을 보조하거나, VulTrial과 같이 여러 Agent가 서로 다른 관점에서 취약 여부를 주장하고 반박하도록 설계하는 연구가 등장하고 있다. 하지만 이러한 방법에서도 결국 중요한 문제는 LLM이 무엇을 근거로 추론하는가라고 생각한다.

CLEAR는 이 문제를 상당히 직접적으로 다룬 연구라고 생각한다. 단순히 유사한 취약점 사례를 검색해서 LLM에게 제공하는 것이 아니라, 취약점을 Entrypoint → Precondition → Root Cause → Fix Intent라는 Causal Chain으로 구조화하고, Multi-Agent가 이 구조를 따라 추론하도록 설계했다는 점이 가장 인상적이었다. 특히 취약 코드와 패치 코드는 대부분의 코드가 동일하기 때문에 단순 Semantic Similarity만으로 구분하기 어렵다는 문제를 Fix Intent라는 개념을 통해 해결하려 했다는 점이 흥미롭다.

또 하나 흥미로운 부분은 RAG와 Multi-Agent의 역할을 명확하게 분리했다는 점이다. VCKG와 Collector는 Agent가 판단할 때 사용할 Evidence를 제공하고, Claim과 Critic은 동일한 Evidence를 서로 다른 관점에서 검증하며, Judge가 이를 종합한다. 즉, Knowledge Graph가 “무엇을 근거로 생각할 것인가”를 제공한다면 Multi-Agent는 “그 근거를 어떻게 검증할 것인가”를 담당하는 구조라고 볼 수 있다.

Ablation 결과도 이러한 설계를 비교적 잘 뒷받침한다. VCKG를 제거하고 Agent만 사용했을 때 PrimeVul P-C가 19.17에서 8.08까지 감소하였으며, 단순 Instance-level 또는 Chunk-level Retrieval 역시 전체 CLEAR보다 크게 낮은 성능을 보였다. 이는 단순히 Agent의 수를 늘리거나 외부 정보를 Retrieval하는 것만으로는 충분하지 않고, 검색된 지식의 구조와 Agent의 검증 과정이 함께 설계되어야 한다는 점을 보여준다고 생각한다.

다만 VCKG가 완전히 객관적인 Causal Graph라고 보기는 어렵다는 점은 한계라고 생각한다. Local VCKG의 Causal Node 자체가 LLM을 통해 생성되고 Neighbor Edge 역시 Semantic Similarity에 상당 부분 의존하기 때문이다. 실제 Human Evaluation에서도 Local VCKG가 4.83/5.0을 기록한 것과 달리 Neighbor Edge는 3.58/5.0으로 상대적으로 낮았다. 따라서 “Semantic Similarity를 넘어 Causality를 모델링한다”는 것이 CLEAR의 핵심 주장인 만큼, 향후에는 AST, Control Flow, Data Flow와 같은 정적 프로그램 분석 정보를 결합하여 Causal Relation 자체를 보다 객관적으로 검증할 필요가 있어 보인다.

또한 현재 CLEAR가 Function-level 분석을 중심으로 한다는 점 역시 실제 소프트웨어 적용에서는 중요한 한계가 될 수 있다. 실제 취약점은 하나의 함수 내부에서 완결되는 경우뿐만 아니라 여러 함수의 호출 관계, 공유 상태, 데이터 흐름 등에 의해 발생하는 경우가 많다. 논문에서도 이를 인식하고 향후 Multi-Procedural VCKG와 Repository-level 분석으로 확장하는 방향을 제시하고 있는데, 개인적으로는 이 부분이 CLEAR의 가장 자연스러운 후속 연구 방향이라고 생각한다.

개인적으로는 이 논문을 통해 “Multi-Agent를 얼마나 복잡하게 구성할 것인가”보다 “Agent가 어떤 근거를 가지고 추론하도록 만들 것인가”가 더 중요할 수 있다는 생각이 들었다. VulTrial이 서로 다른 역할을 가진 Agent 사이의 Debate를 통해 추론의 신뢰성을 높였다면, CLEAR는 한 단계 더 나아가 Debate에 사용되는 Evidence 자체를 Causal Knowledge로 구조화하려고 시도한다. 결국 Multi-Agent의 성능은 Agent의 수나 토론 횟수뿐만 아니라, Agent에게 제공되는 Knowledge의 품질과 구조에 크게 좌우될 수 있다는 것이다.

전반적으로 CLEAR는 `취약점을 인과관계로 정의하고 그래프로 만든 것`, `Knowledge Graph, RAG, Multi-Agent Reasoning을 Causal Reasoning이라는 하나의 관점에서 결합한 연구`라는 점에서 의미가 있어 최종 Accept 되었다고 생각한다.
