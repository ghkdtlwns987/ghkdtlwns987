## 문제 설명

XX게임에는 **피로도** 시스템(0 이상의 정수)이 있으며, 일정 피로도를 사용해서 던전을 탐험할 수 있습니다.

각 던전마다 다음 두 값이 있습니다.

| 용어 | 의미 |
| --- | --- |
| 최소 필요 피로도 | 탐험 **시작**에 필요한 피로도 (이 이상이어야 입장 가능) |
| 소모 피로도 | 탐험 **완료** 후 줄어드는 피로도 |

예: 최소 80, 소모 20 → 피로도 80 이상일 때 입장 가능, 탐험 후 20 감소.

하루에 한 번씩 탐험할 수 있는 던전이 여러 개 있을 때, **최대한 많이** 탐험하려 합니다. 던전 **순서**는 자유롭게 정할 수 있습니다.

유저의 현재 피로도 `k`와 던전 배열 `dungeons`(`[최소 필요, 소모]`)가 주어질 때, 탐험할 수 있는 **최대 던전 수**를 return 하세요.

제한사항
- k는 1 이상 5,000 이하
- 던전 개수는 1 이상 **8 이하**
- 각 행은 `[최소 필요 피로도, 소모 피로도]`
- 최소 필요 피로도 ≥ 소모 피로도

입출력 예

| k | dungeons | result |
| --- | --- | --- |
| 80 | [[80,20],[50,40],[30,10]] | 3 |

입출력 예 설명

현재 피로도 80.

**순서 1 → 2 → 3** (던전 0 → 1 → 2)

| 단계 | 피로도 | 판정 |
| --- | --- | --- |
| 0번 입장 | 80 ≥ 80 | 가능 → 60 남음 |
| 1번 입장 | 60 ≥ 50 | 가능 → 20 남음 |
| 2번 입장 | 20 < 30 | **불가** → 2개만 |

**순서 1 → 3 → 2** (던전 0 → 2 → 1)

| 단계 | 피로도 | 판정 |
| --- | --- | --- |
| 0번 | 80 → 60 | 가능 |
| 2번 | 60 ≥ 30 → 50 | 가능 |
| 1번 | 50 ≥ 50 → 10 | 가능 |

→ **3개** 모두 탐험 가능. 정답은 3.

## DFS부터 이해하기

[타겟 넘버]({{ '/poster/2026/09/03/target-number/' | relative_url }})에서 DFS는 **고정된 순서**로 +/- 를 고르는 **트리** 탐색이었다.

이 문제는 **던전 순서를 바꿀 수 있다**. 8개 던전이면 최악의 경우 8! = 40,320가지 순서 — 던전이 최대 8개라 **모든 순서를 시도**해도 된다.

DFS로 표현하면:

```
현재 피로도 k, 지금까지 탐험한 수 cnt
→ 아직 안 간 던전 i 중 입장 가능한 곳을 골라 재귀
→ 더 이상 갈 데 없으면 되돌아가 다른 순서 시도
```

---

## 백트래킹이란?

**백트래킹(backtracking)** 은 DFS에 **"선택 취소"** 를 더한 것이다.

1. 던전 하나를 **선택**한다 (`visited[i] = 1`)
2. 그 상태로 **더 깊이** 탐색한다 (`dfs(...)`)
3. 돌아올 때 **선택을 되돌린다** (`visited[i] = 0`) → 다른 던전 순서 시도

```
        k=80, cnt=0
       /    |    \
   던전0   던전1  던전2  ... (입장 가능한 것만)
      |
   k=60, cnt=1
   /    \
던전1  던전2
  ...
```

**되돌리기(backtrack)** 가 없으면 "0번 던전을 갔다"는 표시가 영구적으로 남아, 0번을 먼저 안 가는 다른 순서를 탐색할 수 없다.

| | 타겟 넘버 | 피로도 (이 문제) |
| --- | --- | --- |
| 순서 | numbers 순서 **고정** | 던전 순서 **자유** |
| visited | 불필요 (idx만 증가) | **필요** (같은 던전 재사용 불가) |
| 되돌리기 | 없음 (트리 끝까지) | **visited[i] = 0** |
| 목표 | 경우의 수 **합산** | 탐험 수 **최댓값** |

---

## 로직 흐름

```text
dfs(k, cnt):
  1. answer = max(answer, cnt)     ← 지금까지 cnt가 최선인지 갱신
  2. for 각 던전 i:
       - 이미 갔으면 skip (visited[i])
       - k < 최소 필요 피로도면 skip
       - visited[i] = 1             ← 선택
       - dfs(k - 소모, cnt + 1)     ← 다음 던전 탐색
       - visited[i] = 0             ← 취소 (백트래킹)
```

- **매 재귀 진입마다** `answer = max(answer, cnt)` — 중간에 더 갈 곳이 없어도, 지금까지의 cnt가 후보
- `for` 루프가 **다음에 갈 던전**을 고른다
- 입장 조건 `k >= dungeons[i][0]` 미달 시 그 가지는 탐색하지 않음 (가지치기)

### visited를 쓰는 이유

같은 던전은 **하루에 한 번**만 탐험한다. 한 경로 안에서 0번 던전을 두 번 가면 안 되므로, 현재 경로에서 사용 중인 던전을 `visited`로 표시한다.

탐색이 끝나면 `visited[i] = 0`으로 **다른 순서**에서 i번 던전을 쓸 수 있게 한다. 이것이 백트래킹의 핵심이다.

---

## DFS 입문자를 위한 팁

1. **상태 두 개** — `k`(남은 피로도), `cnt`(탐험 개수). 재귀마다 같이 넘긴다.
2. **전역/바깥 변수 `answer`** — 모든 경로 중 최댓값. `nonlocal answer`로 갱신.
3. **base case가 명시적이지 않아도 됨** — 더 갈 던전이 없으면 for가 돌지 않고 return. 그 전에 `max(answer, cnt)` 호출.
4. **visited는 "현재 경로"용** — 백트래킹 문제에서 거의 필수.
5. **던전 8개 이하** — 완전 탐색·백트래킹이 통하는 이유. n이 크면 DP/그리디 등 다른 방법 필요.

---

### Solution

```python
def solution(k, dungeons):
    answer = 0
    visited = [0] * len(dungeons)

    def dfs(k, cnt):
        nonlocal answer
        answer = max(answer, cnt)

        for i in range(len(dungeons)):
            if visited[i] == 1:
                continue
            if k >= dungeons[i][0]:
                visited[i] = 1
                dfs(k - dungeons[i][1], cnt + 1)
                visited[i] = 0

    dfs(k, 0)
    return answer
```

- `dfs(k, 0)` : 현재 피로도 `k`, 아직 0개 탐험한 상태에서 시작
- `visited[i] = 1` → 탐험 → `dfs` → `visited[i] = 0` : **선택과 취소** 한 세트
- `answer = max(answer, cnt)` : 모든 깊이에서 최대 탐험 수 갱신

## 정리

| 키워드 | 내용 |
| --- | --- |
| 알고리즘 | DFS + **백트래킹** |
| visited | 현재 경로에서 사용한 던전 표시 |
| 백트래킹 | `visited[i] = 0`으로 선택 취소 |
| 가지치기 | `k < 최소 필요 피로도`면 skip |
| 답 | 모든 순서 중 `cnt` **최댓값** |

**순서가 중요하고, 같은 원소를 재사용하지 않는** 탐색은 visited + 백트래킹 패턴이 전형적이다. 타겟 넘버가 "고정 순서 트리"였다면, 피로도는 "순열 + 되돌리기" 문제다.

```text
DFS     : 깊이 우선으로 가능한 길 탐색
백트래킹 : 막히거나 분기 끝나면 한 단계 되돌아가 다른 선택 시도
visited : 지금 경로에서 이미 쓴 던전 표시 → 취소할 때 0으로 복구
```

이 세 가지를 함께 기억하면 비슷한 "최대/최소 순서 탐색" 문제에도 같은 틀을 적용할 수 있다.
