## 문제 설명

0 또는 양의 정수가 주어졌을 때, 정수를 이어 붙여 만들 수 있는 가장 큰 수를 알아내 주세요.

예를 들어, 주어진 정수가 `[6, 10, 2]`라면 `[6102, 6210, 1062, 1026, 2610, 2106]`를 만들 수 있고, 이중 가장 큰 수는 **6210**입니다.

0 또는 양의 정수가 담긴 배열 `numbers`가 주어질 때, 순서를 재배치하여 만들 수 있는 가장 큰 수를 **문자열**로 return 하세요.

제한 사항
- `numbers`의 길이는 1 이상 100,000 이하
- 원소는 0 이상 1,000 이하
- 정답이 너무 클 수 있으니 문자열로 return

입출력 예

| numbers | return |
| --- | --- |
| [6, 10, 2] | "6210" |
| [3, 30, 34, 5, 9] | "9534330" |

---

## 숫자 크기 순으로 붙이면 안 된다

순열을 모두 만들어 최댓값을 고르면 길이가 100,000일 때 불가능하다. **정렬 한 번**으로 붙여야 한다.

다만 일반 정렬은 답이 아니다.

| 정렬 | [6, 10, 2] | 붙인 결과 | 왜 안 되나 |
| --- | --- | --- | --- |
| 숫자 내림차순 | 10, 6, 2 | 1062 | 10이 6보다 커서 앞에 감. **6210**이 더 큼 |
| 문자열 내림차순 | 6, 2, 10 | 6210 | 이 예는 맞지만, `[3, 30]`이면 `"30" > "3"` 이라 **303**이 됨. 정답은 **330** |

앞자리가 같아도 **자릿수가 다른 수**가 있으면, "큰 숫자"와 "먼저 붙였을 때 큰 문자열"이 어긋난다. `3`과 `30`이 전형적인 예다.

---

## 비교 기준: 어느 쪽을 앞에 붙일까

두 수 `a`, `b`만 있으면 순서는 두 가지다. **이어 붙인 문자열**이 더 큰 쪽을 고르면 된다.

```text
a + b  >  b + a  이면  a가 앞
아니면              b가 앞
```

```
3, 30  →  "330" vs "303"  →  330이 더 큼  →  3이 앞
6, 10  →  "610" vs "106"  →  610이 더 큼  →  6이 앞
34, 3  →  "343" vs "334"  →  343이 더 큼  →  34가 앞
```

모든 쌍에 이 순서를 적용해 정렬하면, 앞에서부터 붙인 값이 최댓값이 된다. (이 비교는 전이성이 있어서 정렬 키로 쓸 수 있다.)

파이썬에서 직접 쓰면 `cmp_to_key`로 `a+b`와 `b+a`를 비교하면 된다. 같은 뜻을 **정렬 키 하나**로 바꾼 것이 아래 `x * 3`이다.

---

## 왜 `x * 3` 인가

원소가 최대 1,000 이라 문자열 길이는 최대 4다. 길이가 다른 문자열을 그냥 비교하면 `"3"`과 `"30"`처럼 짧아서 지거나 이긴다.

문자열을 **여러 번 이어 붙여** 앞자리를 충분히 펼쳐 놓고 비교하면, "앞에 붙였을 때 어떤 숫자가 이어지는지"가 키에 드러난다.

```text
6  →  666
10 →  101010
2  →  222

내림차순: 666 > 222 > 101010   ('6' > '2' > '1')
순서: 6, 2, 10  →  "6210"
```

```text
3  →  333
30 →  303030
34 →  343434
5  →  555
9  →  999

내림차순: 9, 5, 34, 3, 30
→ "9534330"
```

`3` vs `30`: `"333"` vs `"303030"` → 두 번째 글자 `'3' > '0'` 이라 `3`이 앞. `"330" > "303"`과 같다.

3번 반복하는 이유는, 최대 세 자릿수끼리 비교할 때 앞자리가 한 바퀴 이상 겹치도록 하기 위해서다. (1,000은 네 자리지만 이 방식으로도 통과한다.)

---

## `[0, 0, 0]` → `"0"`

정렬 후 `join`만 하면 `"000"`이 된다. 가장 큰 수는 **0 하나**이므로, 한 번 정수로 바꿨다가 다시 문자열로 만든다.

```python
str(int("".join(numbers)))
```

문제에서 문자열로 return 하라고 한 것은 값이 커서 정수 overflow를 피하려는 것이고, 파이썬 `int`는 이 정도에서 문제 없다. 여기서 `int`를 쓰는 이유는 overflow가 아니라 **선행 0 제거**다.

---

### Solution

```python
def solution(numbers):
    # Key Idea : 정수형을 문자열로 바꾸고, 문자열을 여러번 곱한걸 기준으로 정렬한다.
    """
    6 -> 666
    10 -> 101010
    2 -> 222
    """
    numbers = list(map(str, numbers))
    numbers.sort(key = lambda x : x * 3, reverse = True)

    answer = str(int("".join(numbers)))
    return answer
```

- `map(str, numbers)` : 이어 붙이려면 처음부터 문자열
- `key = lambda x: x * 3` : 반복한 문자열을 비교 키로. `reverse=True` 로 큰 키가 앞
- `str(int(...))` : `"000"` 같이 0만 있는 입력을 `"0"`으로

같은 비교를 명시적으로 쓰면 아래와 같다. 의미는 `a+b` vs `b+a`다.

```python
from functools import cmp_to_key

def solution(numbers):
    numbers = list(map(str, numbers))
    numbers.sort(key=cmp_to_key(lambda a, b: (a + b < b + a) - (a + b > b + a)))
    return str(int("".join(numbers)))
```

## 정리

| 키워드 | 내용 |
| --- | --- |
| 알고리즘 | 정렬 (그리디 비교) |
| 함정 | 숫자 크기·일반 문자열 정렬로는 부족 (`3` vs `30`) |
| 비교 | `a+b`와 `b+a` 중 큰 쪽이 앞 |
| 구현 | `key = lambda x: x * 3`, `reverse=True` |
| 예외 | 전부 0이면 `"0"` (`str(int(...))`) |

이어 붙여 최댓값을 만드는 문제는 "값의 크기"가 아니라 **앞에 놓았을 때 만들어지는 문자열**로 순서를 정한다.
