## 문제 설명

운영체제가 아래 규칙으로 프로세스를 관리할 때, 특정 프로세스가 **몇 번째로 실행되는지** 구하면 됩니다.

1. 실행 대기 큐에서 대기 중인 프로세스 하나를 꺼냅니다.
2. 큐에 대기 중인 프로세스 중 **우선순위가 더 높은** 프로세스가 있다면, 방금 꺼낸 프로세스를 다시 큐에 넣습니다.
3. 그런 프로세스가 없다면 방금 꺼낸 프로세스를 실행합니다.
   - 한 번 실행한 프로세스는 다시 큐에 넣지 않고 종료됩니다.

예를 들어 프로세스 `[A, B, C, D]`가 순서대로 대기 큐에 있고 우선순위가 `[2, 1, 3, 2]`이면 실행 순서는 `[C, D, A, B]`입니다.

대기 큐의 중요도가 담긴 배열 `priorities`와, 알고 싶은 프로세스의 위치 `location`이 주어질 때, 그 프로세스가 몇 번째로 실행되는지 return 하세요.

제한사항
- `priorities` 길이는 1 이상 100 이하
- 원소는 1 이상 9 이하. **숫자가 클수록 우선순위가 높음**
- `location`은 0 이상 (프로세스 수 - 1) 이하. 맨 앞이 0

입출력 예

| priorities | location | return |
| --- | --- | --- |
| [2, 1, 3, 2] | 2 | 1 |
| [1, 1, 9, 1, 1, 1] | 0 | 5 |

예제 #1 — 문제에 나온 예와 같습니다. location 2는 C이고, C가 첫 번째로 실행됩니다.

예제 #2 — `[A, B, C, D, E, F]`, 중요도 `[1, 1, 9, 1, 1, 1]` → 실행 순서 `[C, D, E, F, A, B]`. A는 5번째입니다.

## 큐를 그대로 시뮬레이션한다

규칙은 대기 큐의 정의 그대로다. 앞에서 꺼내서, 뒤에 더 급한 게 있으면 **맨 뒤로 보내고**, 없으면 실행한다.

[주식가격]({{ '/poster/2026/09/02/stock-price/' | relative_url }})이 스택으로 "아직 처리 안 된 인덱스"를 쌓는 문제라면, 이 문제는 **앞에서 빼고 조건에 따라 뒤에 넣는 큐** 문제다.

알아야 하는 것은 우선순위만이 아니다. `location`은 **처음 배열에서의 위치**다. 큐에서 순서가 바뀌어도 "몇 번 프로세스인지"를 붙여 다녀야 한다.

```python
q.append((i, priorities[i]))   # (원래 인덱스, 우선순위)
```

실행할 때마다 카운트를 올리고, 꺼낸 `idx`가 `location`이면 그 카운트가 답이다. 나머지 프로세스까지 돌 필요 없다.

우선순위가 더 높은 게 있는지는, 꺼낸 값보다 **큰 우선순위가 큐에 하나라도 있는지** 보면 된다.

```python
if any(priority < num for _, num in q):
    q.append((idx, priority))   # 뒤로 보냄
else:
    실행
```

`priorities` 길이가 최대 100이라, 매번 큐를 훑어도 O(n²)로 충분하다.

## 예제 추적

예제 1: `priorities = [2, 1, 3, 2]`, `location = 2`

```text
큐: (0,2) (1,1) (2,3) (3,2)

꺼냄 (0,2)  남은 최댓값 3 > 2  →  뒤로
큐: (1,1) (2,3) (3,2) (0,2)

꺼냄 (1,1)  남은 최댓값 3 > 1  →  뒤로
큐: (2,3) (3,2) (0,2) (1,1)

꺼냄 (2,3)  남은 최댓값 2 < 3  →  실행 1번째
idx == 2 == location  →  return 1
```

예제 2: location 0인 A(우선순위 1). 가운데 9가 먼저 실행되고, 그 뒤 1들이 순서대로 돈다. A는 맨 앞에서 뒤로 밀렸다가 마지막에서 두 번째로 실행된다 → 5번째.

큐가 비기 직전에 마지막 하나를 꺼내면 `any(...)`는 빈 큐에서 False라서 바로 실행한다.

---

### Solution

```python
from collections import deque
def solution(priorities, location):
    q = deque()

    for i in range(len(priorities)):
        q.append((i, priorities[i]))

    cnt = 0

    while q:
        idx, priority = q.popleft()

        if any(priority < num for idx, num in q):
            q.append((idx, priority))
        else:
            cnt += 1
            if idx == location:
                return cnt
```

- `(i, priorities[i])` : 순서가 바뀌어도 처음 위치를 기억
- `popleft()` 후 더 높은 우선순위가 있으면 `append`로 뒤로
- 없으면 실행 (`cnt += 1`). 목표가 실행되면 그 순서를 return
- `any(...)` 안의 `idx`는 제너레이터 지역 변수라, 바깥에서 꺼낸 `idx`를 덮어쓰지 않는다

`max(q)`로 비교해도 되지만, 우선순위만 보려면 `any`가 의도에 더 가깝다. "나보다 급한 프로세스가 **하나라도** 있는가?"

## 정리

| 키워드 | 내용 |
| --- | --- |
| 자료구조 | Queue (`deque`) |
| 상태 | `(원래 인덱스, 우선순위)` |
| 규칙 | 앞에 꺼냈는데 뒤에 더 높으면 다시 뒤로 |
| 실행 | 더 높은 우선순위가 없을 때. 한 번 실행하면 종료 |
| 답 | `location` 인덱스가 실행된 시점의 순서 |

우선순위 큐(힙)로 매번 최댓값을 뽑아 실행하는 문제가 아니다. **대기 순서와 우선순위를 함께** 지키면서, 큐를 한 바퀴 돌리는 시뮬레이션이다.
