## 문제 설명

프로그래머스 팀에서는 기능 개선 작업을 수행 중입니다. 각 기능은 진도가 100%일 때 서비스에 반영할 수 있습니다.

또, 각 기능의 개발속도는 모두 다르기 때문에 뒤에 있는 기능이 앞에 있는 기능보다 먼저 개발될 수 있고, 이때 뒤에 있는 기능은 **앞에 있는 기능이 배포될 때 함께 배포**됩니다.

먼저 배포되어야 하는 순서대로 작업의 진도가 적힌 정수 배열 progresses와 각 작업의 개발 속도가 적힌 정수 배열 speeds가 주어질 때, **각 배포마다 몇 개의 기능이 배포되는지**를 return 하도록 solution 함수를 완성하세요.

제한 사항
- 작업의 개수(progresses, speeds 배열의 길이)는 100개 이하입니다.
- 작업 진도는 100 미만의 자연수입니다.
- 작업 속도는 100 이하의 자연수입니다.
- 배포는 하루에 한 번만 할 수 있으며, 하루의 끝에 이루어진다고 가정합니다. 예를 들어 진도율이 95%인 작업의 개발 속도가 하루에 4%라면 배포는 2일 뒤에 이루어집니다.

입출력 예

| progresses | speeds | return |
| --- | --- | --- |
| [93, 30, 55] | [1, 30, 5] | [2, 1] |
| [95, 90, 99, 99, 80, 99] | [1, 1, 1, 1, 1, 1] | [1, 3, 2] |

입출력 예 설명

입출력 예 #1

- 1번 기능: 93% → 하루 1% → **7일** 후 100%
- 2번 기능: 30% → 하루 30% → **3일**이면 끝나지만, 1번이 7일째에 끝나므로 **7일째 함께** 배포
- 3번 기능: 55% → 하루 5% → **9일** 후 배포

→ 7일째 2개, 9일째 1개 → `[2, 1]`

입출력 예 #2

남은 일수는 각각 5, 10, 1, 1, 20, 1일이지만, **앞 기능이 끝나야** 뒤 기능도 배포된다.

→ 5일째 1개, 10일째 3개, 20일째 2개 → `[1, 3, 2]`

## 문제 풀이

문제는 두 단계로 나눌 수 있다.

1. **각 기능이 100%가 되는 데 걸리는 일수**를 구한다.
2. **같은 날(같은 배포 묶음)에 배포되는 기능**을 센다.

---

### 1단계: 완료까지 걸리는 일수

하루가 끝날 때마다 `speeds[i]`만큼 진도가 오른다. 100% 이상이 될 때까지 반복하면 된다.

```python
current = progresses[i]
cnt = 0
while current < 100:
    current += speeds[i]
    cnt += 1
```

예: 93%, 속도 1 → 7일  
예: 30%, 속도 30 → 3일

이 값들을 배열(코드에서는 `stack`)에 저장한다.

---

### 2단계: 배포 묶음 묶기

**앞 기능이 배포되기 전에는 뒤 기능도 배포되지 않는다.**

따라서 순서대로 보면서, **현재 배포 묶음의 기준 일수**보다 먼저(또는 같은 날) 끝나는 기능들은 한 번에 배포된다.

```
days = [7, 3, 9]

묶음 1: 기준 7일
  - 1번: 7일 → 포함
  - 2번: 3일 → 7일 전에 끝남, 하지만 1번 기다림 → 함께 배포
묶음 2: 기준 9일
  - 3번: 9일 → 7일보다 늦음 → 새 묶음
```

조건: `current >= stack[i]`

- `current` : 지금 배포 묶음에서 **가장 늦게 끝나는(=실제 배포일)** 기능의 일수
- `stack[i]` : i번 기능이 혼자서 끝나는 데 걸리는 일수
- i번 기능이 `current`일 이전에 끝날 수 있으면 → 같은 배포에 포함
- 더 늦게 끝나면 → 새 배포 묶음 시작

입출력 예 #2: `[5, 10, 1, 1, 20, 1]`

```
5일  → [1]           (1개)
10일 → [10, 1, 1]    (3개, 1·1·1일짜리가 10일 묶음에 합류)
20일 → [20, 1]       (2개)
```

---

### Solution

```python
def solution(progresses, speeds):
    answer = []
    stack = []

    for progress in range(len(progresses)):
        current = progresses[progress]
        cnt = 0
        while True:
            if current >= 100:
                stack.append(cnt)
                break
            current += speeds[progress]
            cnt += 1

    current = stack[0]
    cnt = 1

    for i in range(1, len(stack)):
        if current >= stack[i]:
            cnt += 1
        else:
            answer.append(cnt)
            current = stack[i]
            cnt = 1

    answer.append(cnt)
    return answer
```

- 1번 `for` : 기능별 **완료 일수** 계산 → `stack`
- 2번 `for` : `current`(배포 기준일)와 비교하며 **묶음 개수** `cnt` 집계
- 마지막 `answer.append(cnt)` : 마지막 묶음 push (for 루프 밖에서 한 번 더 필요)

## 정리

| 키워드 | 내용 |
| --- | --- |
| 1단계 | 각 기능 완료까지 걸리는 일수 |
| 2단계 | 기준일보다 일찍 끝나는 뒤 기능 → 같은 배포 |
| 핵심 | `current >= stack[i]` 이면 같은 묶음 |
| 주의 | 마지막 묶음 `answer.append` 잊지 않기 |

**앞 기능의 배포 시점이 뒤 기능의 상한**이라는 점이 이 문제의 본질이다. 완료 일수만 구하고 정렬하는 것이 아니라, **순서를 유지한 채 묶음**을 세야 한다.

[올바른 괄호]({{ '/poster/2026/09/02/correct-parentheses/' | relative_url }})에서 stack을 LIFO로 썼다면, 이번에는 **완료 일수 배열 + 순차 그룹핑**에 가깝지만, 계산한 일수를 stack에 쌓아 두고 처리하는 흐름은 비슷하다.
